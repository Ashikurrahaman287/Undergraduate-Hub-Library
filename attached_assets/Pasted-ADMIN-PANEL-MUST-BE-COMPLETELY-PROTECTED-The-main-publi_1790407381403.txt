Do NOT implement Email OTP for members.

Member authentication must use:

Supported format examples:

15. PHONE OTP FLOW

Member login/registration:

Enter phone number
        ↓
Validate Bangladesh number
        ↓
Check rate limit
        ↓
Generate cryptographically secure OTP
        ↓
Hash OTP before storing
        ↓
Store expiration time
        ↓
Send OTP through SMS provider
        ↓
User enters OTP
        ↓
Verify hashed OTP
        ↓
Check expiration
        ↓
Check maximum attempts
        ↓
Mark OTP as consumed
        ↓
Authenticate user through Supabase Auth
        ↓
Create secure authenticated session
        ↓
Redirect to member dashboard

OTP requirements:

6-digit numeric OTP
Cryptographically secure random generation
Expiration: approximately 5 minutes
One-time use
Maximum verification attempts
Resend cooldown
IP rate limiting
Phone-number rate limiting
Failed-attempt tracking
OTP must be invalidated after successful verification
Old OTPs must become invalid when a new OTP is generated

Never store OTPs in plaintext.

Store a secure hash.

19. OTP RATE LIMITING

Implement strong anti-abuse protection.

Recommended limits:

Per phone:

Maximum OTP requests per short period
Resend cooldown
Daily reasonable limit

Per IP:

Maximum OTP requests per minute/hour
Maximum verification attempts

Per OTP:

Maximum failed attempts
Expire automatically
Immediately invalidate after success

Return generic messages where appropriate so attackers cannot easily enumerate registered accounts.

Example:

If an account exists, an OTP has been sent to your phone.

Do not expose unnecessary account-existence information.

20. SUPABASE AUTH + PHONE OTP

Supabase Auth must remain the identity/authentication foundation.

Do NOT create a completely separate homemade authentication system.

The application-level SMS OTP service must be designed as an authentication layer that securely integrates with Supabase Auth.

The implementation must ensure that:

Successful OTP verification
        ↓
Verified identity
        ↓
Supabase Auth authenticated session

Server-side authorization

Do not simply set:

Do not manually trust a phone number supplied by the browser after OTP verification.

The authenticated Supabase user ID must become the permanent identity reference.
